# Skill toolkit v2 candidate

`full-client-skill-toolkit-v2` is an explicit opt-in fixture and control policy.
The default toolkit and every historical native/productivity contract, program,
prompt and fixture output retain their prior values. The hash regression binds
those values to the pre-successor source revision. This is source readiness;
every mapped skill still requires independent live effect review.

The successor binds the repaired Hero Combo/Advanced Combo and physical Sharp
Eyes calculations, and the Bowmaster Hurricane port timing:960 ms preparation,
then120 ms simulation intervals while held. The new recipe and manual Hurricane
button hold for1,500 ms, within the existing SDK limit. It does not claim original
client animation or cadence fidelity. Hero learns Achilles 1120004 level 30 only
with the 0022 authority repair and matched `x=850` definition.

Night Lord adds Shadow Partner 4111002 level 30 on `SKILL_9` and Shadow Stars
4121006 level 30 on `SKILL_10`. Shadow Partner's actual `itemCon` is 4006001,
Summoning Rock; 4006000 is a different item and is rejected. The v2 fixture puts
ten Summoning Rocks in ETC. Their matched item definition omits `slotMax`, for
which the ordinary item provider uses 100. Partner consumes one rock; Stars
requires its 200-star activation fee from a single real stack. Runtime resource
consumption remains server-owned.

V2 replaces the entire offline USE and ETC inventories with their declared
contents. Night Lord USE remains exactly 24 slots: 100 shared Power Elixirs and
23 stacks of 800 Ilbi stars. ETC contains only the ten rocks; other v2 classes
have an empty ETC tab. V1 still replaces only USE and preserves ETC. Account
bytes, equipped gear and unrelated SQL remain unchanged, and the input baseline
is retained. Exact before/saved/restored inventory receipts remain necessary;
the transform itself does not touch a database or qualify resources.

The separate `scripted-native-toolkit-acceptance-v2` recipe has a120-second
executor ceiling,128-action/600-SDK-request bounds and125,000 ms encoded capture
bound. It stops admitting inputs at112 seconds, retains a short observation
tail, and reports actual duration. There is no claim of 120 seconds of continuous
combat. It accepts only its canonical generated program, makes no model call,
and performs no hidden position, skill, orb or inventory mutation.

Each damage cast gets fresh targeting, approach and facing observations. Missing
or unreachable targets cause that cast opportunity to be skipped. Buff and
movement probes retain before, immediate and settled observations; Hurricane
gets a held-input opportunity, Hero rebuilds orbs between finishers, and Night
Lord gets attack opportunities before and after Partner/Stars. None of these
inputs or acknowledgements certifies a hit, buff, summon, consumption or kill.

Remaining exclusions include Night Lord Flash Jump, unqualified summons and
their presentation/AI, Mage Big Bang charge/release, and the original-client
contact defense/RNG formula. The four prior classes' published controls and
model previews do not qualify these new mechanics or this new fixture.
