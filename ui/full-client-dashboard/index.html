Simulation labInside the distributed setup

What the agent sees

Position, HP/MP, XP, level, map, alive status, and nearby monsters. The model receives structured state; the recording is for us.

What it controls

A program calls observe(), pressKeys(), and wait() in Node.js / Docker. Normal game inputs only; no stat edits.

An agent’s program Illustrative

const state = await sdk.observe();
if (state.character.hp < state.character.maxHp / 2) {
  await sdk.pressKeys(['HP_POTION'], 100);
}
await sdk.pressKeys(['LEFT'], 300);
await sdk.pressKeys(['PRIMARY_SKILL'], 650);

Each worker owns its world, database, baseline, credentials, and locks. Trials run serially per worker; cohorts stay on one host. Provisioning alone does not establish qualification. An external controller verifies worker deletion at lease expiry.

    Methodology

    Score

    Saved XP after logout minus starting XP, including penalties. Live XP is diagnostic. Missing scores stay missing.

    Comparisons

    Groups share a baseline, scenario, budgets, and runtime settings. Live scenes can differ. Small samples do not establish statistical significance.

    Evidence

    Input and publication checks are separate from scores. Failed, recovered, and zero-input attempts remain in the history.

    Research framing and score limits

    Scoring progress

    The score is the change in persisted XP after ordinary logout. It includes penalties. Live XP is diagnostic and is kept separate from the saved result. A missing verified score is shown as missing, never silently turned into zero.

    Strategy discovery is the research goal

    Given the same starting conditions, tools, and time budget, how effectively does an agent discover a training strategy? The intended 30-minute benchmark measures the best normalized XP/min in complete 15-second authoritative windows. These five-minute pilots report saved net XP; their endpoints cannot reconstruct a peak rate. Native scoring and expanded skill toolkits are implemented in source and still need runtime qualification. Read the research framing.

    Reading these results

    This is a development benchmark with a small number of attempts. Frozen-input groups share a baseline, scenario, budgets, and runtime settings. They do not establish identical live scenes or statistical significance. Publication evidence is checked separately from the persisted score.

    Learning from the whole run

    An agent may gain XP, execute inputs without gaining XP, or exit without sending any inputs. The recordings make those differences inspectable. Failed and recovered attempts stay in the history even when no score can be verified.
